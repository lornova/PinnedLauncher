## 1. Identities in play, and their consumers

Two generated identifiers exist per launcher, both fixed at creation:

- the **slug**: the launcher's internal identity, and
- the **AUMID** `PinnedLauncher.Proxy.<slug>`: the slug's shell-visible form.

Every consumer, with the identifier it keys on:

| Consumer | Keys on | Source |
|---|---|---|
| Proxy `.lnk` property store (`System.AppUserModel.ID`, stamped before pinning) | AUMID | architecture §2, S-3 |
| Jump-list publisher (`SetAppID` on `ICustomDestinationList`; `DeleteList` at removal) | AUMID | architecture §4.1, S-7 |
| Pin guide deep link + indexing poll (`ParseName` / `SHOpenFolderAndSelectItems` on `shell:AppsFolder\<AUMID>`) | AUMID | S-4, S-6 |
| Pin-request helper (`--request-pin` assumes the identity via `SetCurrentProcessExplicitAppUserModelID`, then `RequestPinCurrentAppAsync`) | AUMID | architecture §5, S-8 |
| Pinned-copy watcher and hygiene sweeps (read the copy's retained property store) | AUMID | S-4, S-9 |
| QT oracle (`AutomationId == "Appid: <AUMID>"`, matched prefix-tolerantly) | AUMID | S-9, ADR-0009 |
| Config entry, CLI arguments (`--edit <slug>`, …), icon artifact `icons\<slug>.ico` | slug | config-schema §5/§6, architecture §4.1 |

A packaged *target's* AUMID (`target.aumid`, config-schema §5.1) is a foreign
identity owned by that package; this scheme never generates, parses, or
constrains it.

## 2. Format and namespaces

```
PinnedLauncher.Proxy.<slug>
```

- The documented constraints on an explicit AUMID are a length limit of **128
  characters** and **no spaces** (the `appids` docs cited in architecture §2;
  segments are conventionally dot-separated). The fixed prefix
  `PinnedLauncher.Proxy.` is 21 characters; with the slug capped at 32 + a
  collision suffix (§3), the total stays under 60, leaving wide margin.
- The **scheme is fixed by design** (UC-10): changing it would orphan every
  existing pin and jump list. Should it ever have to change, the stored `aumid`
  field stays authoritative for existing launchers (config-schema §5) and the
  change is an alpha breaking change with documented repair steps
  (release-plan §1); from 0.8 it is effectively frozen.
- Reserved namespaces, disjoint by their second segment:

| Namespace | Owner | Rule |
|---|---|---|
| `PinnedLauncher.Proxy.*` | the product's launchers | generated only by the creation flow defined here |
| `PinnedLauncher.Manager` | the management window's own process identity | set explicitly at startup so the manager's taskbar button can never associate with any launcher pin (§5) |
| `PinnedLauncher.Test.*` | QT articles and harness (S-9) | never generated by product code; hygiene sweeps match **this namespace only** and must never select `Proxy.*` (the S-9 report correction, 2026-08-16, is binding) |
| `PinnedLauncher.S3.*` … `PinnedLauncher.S9.*` | historical spike articles | retired with P0.2; nothing generates them anymore |

Disjointness is structural: the product generates only `Proxy.<slug>`, tests
only `Test.*`, and the second segment differs by construction, so no slug value
can ever make a product AUMID collide with a test or manager identity.

## 3. Slug generation

Computed **once**, at launcher creation, from the initial display name; never
recomputed afterward (§5). The algorithm:

1. Start from `displayName` as entered at creation.
2. **Fold diacritics**: normalize to form D (`NormalizeString(NormalizationD)`)
   and drop combining marks, so `Caffè` → `Caffe`, `Előadó` → `Eloado` (the
   documented normalization API; no transliteration tables, Q-3).
3. **Filter and lowercase**: ASCII letters and digits are kept, lowercased;
   every maximal run of any other character (spaces, punctuation, symbols,
   remaining non-ASCII) becomes a single hyphen `-`.
4. Trim leading and trailing hyphens.
5. Truncate to **32 characters**; trim a trailing hyphen the cut may expose.
6. If the result is empty (a display name with no ASCII-representable
   characters, e.g. fully CJK), use the fallback base `launcher`.
7. **Ensure uniqueness** (ordinal comparison against the slug of *every* entry
   currently in the config, all lifecycle states including `removed`
   tombstones): if taken, append `-2`, `-3`, …, first free number wins.

Resulting alphabet: `a-z`, `0-9`, `-`. Lowercase-only generation makes
case-collisions impossible, and every consumer compares slugs and AUMIDs as
exact ordinal strings (the S-9 oracle's prefix tolerance concerns the
`"Appid: "` prefix Windows adds, not the AUMID itself).

Examples: `Notepad` → `notepad`; `Visual Studio 2026` → `visual-studio-2026`;
`Éditeur` → `editeur`; `画像ビューア` → `launcher` (or `launcher-2` if taken).

The slug is an internal identity, not a user-facing name: lossy derivation from
exotic display names is acceptable because the user only ever sees
`displayName`, and the pin, Start entry, and jump list all render that
(config-schema §5).

## 4. Collision handling

Two independent namespaces can collide; each has one rule:

- **Slug collisions** (two launchers whose names reduce to the same slug):
  resolved at creation by the `-N` suffix (§3 step 7). Because uniqueness is
  checked against every entry still present in the file, a launcher in any
  pending or removal state keeps its slug reserved. After a normal removal
  *completes*, its config entry is deleted (architecture §4.3) and the slug
  becomes reusable; that is safe because completion ordering guarantees every
  AUMID-keyed artifact is already gone: pin unpinned first, jump list
  `DeleteList`ed, `.lnk` and icon deleted (UC-3). Because pin observation is
  best-effort (architecture §4.3), reuse carries one guard (added after the
  2026-08-16 external review): at creation, before the pin flow starts, the
  pipeline probes for an existing pinned copy carrying the new launcher's
  AUMID; one that exists is stale residue from an imperfectly observed removal
  and is **unpinned programmatically first** (UC-3's tolerant `RemoveFromList`
  leg), never adopted. **Accepted residual** (2026-08-16, second review round):
  the removal observation and this probe read the *same* pinned-copy signal,
  so a hypothetical state where the copy is gone while the shell still shows
  the pin would defeat both at once. No spike ever observed that state (S-4
  measured the copy signal as synchronous and route-independent), and its
  consequence is bounded to the user's own old pin launching the user's own
  new launcher; per the project's proportion rule (docs/README.md, Spirit) no
  durable retired-slug ledger is kept for it.
- **Proxy `.lnk` filename collisions** (the Start-menu folder is a flat file
  namespace keyed by display name, not by slug): the filename is
  `<displayName>.lnk` with filesystem-invalid characters (`\ / : * ? " < > |`
  plus ASCII control characters) each replaced by `-`, trailing dots and
  spaces trimmed, and the name component truncated so the full path stays
  inside the shell's `MAX_PATH` budget; if the result is empty or a reserved
  device name (`CON`, `PRN`, …), the slug is used instead. If the file already
  exists in our folder, append ` (2)`, ` (3)`, … (Explorer's own convention).
  The `.lnk` filename is what the All-apps view displays, so a sanitized or
  suffixed name is user-visible there; accepted, it is the same convention
  Explorer applies to copies. The chosen path is recorded in `proxyLnkPath`
  (config-schema §5), so reconciliation never has to re-derive it. This rule
  also covers a launcher named "PinnedLauncher" colliding with the manager's
  own Start entry in the same folder.

All launcher artifacts live in the Start-menu subfolder
`%APPDATA%\Microsoft\Windows\Start Menu\Programs\PinnedLauncher\` (as the
config-schema §3 example shows). One S-5 incidental finding applies: a
subfolder holding a single `.lnk` is flattened in the All-apps view; no design
element may assume the folder is visible as a folder (the pin guide's deep link
pre-selects by AUMID and is unaffected).

## 5. Stability guarantees

- **The slug is immutable** (config-schema §5), therefore the AUMID is
  immutable, therefore renames and icon edits never change what the pin, the
  jump list, and the icon path are keyed on. A rename regenerates the `.lnk`
  (new filename, same AUMID; property store preservation through `IShellLink`
  edits verified by S-5) and re-pins per architecture §4.2; `proxyLnkPath` is
  updated in the same config commit; the icon path `icons\<slug>.ico` never
  moves (the S-5 path-stability rule, config-schema §6).
- **The manager's identity is constant**: `PinnedLauncher.Manager`, set via
  `SetCurrentProcessExplicitAppUserModelID` at process start, before any window
  exists (the documented ordering requirement). This keeps the manager's own
  taskbar button deterministic and guarantees it can never merge with a
  launcher pin, whatever a launcher is named (S-3's A1 finding shows how
  identity accidents look; an explicit AUMID forecloses them).
- **The proxy's launch verb sets no identity**: it is windowless and exits
  immediately (NF-2), so it never surfaces on the taskbar. Only the
  `--request-pin` verb assumes an identity, the launcher's own AUMID, for the
  lifetime of the consent dialog (S-8; contract in `cli.md`).

## 6. Decisions recorded by this document

Local choices not directly derivable from the cited authorities, surfaced per
the P1 ground rule and **accepted as proposed 2026-08-16**. None became ADR
material: the scheme itself
(`PinnedLauncher.Proxy.<slug>`, fixed, test namespace disjoint) is already
decided in the architecture and UC-10; these are its parameters:

1. **Slug alphabet and algorithm** (§3): lowercase `a-z0-9-`, diacritic folding
   via `NormalizeString` form D, hyphen-collapsed separators, 32-character cap,
   `launcher` fallback base.
2. **Uniqueness domain and reuse** (§4): uniqueness against all entries in the
   current config including tombstones; `-N` suffix on collision; slug reuse
   permitted after a normal removal completes (justified by the UC-3 artifact
   ordering).
3. **Proxy `.lnk` filename rule** (§4): sanitized display name, Explorer-style
   ` (N)` disambiguation, slug fallback, recorded in `proxyLnkPath`.
4. **`PinnedLauncher.Manager` as the management window's explicit process
   AUMID** (§2, §5). Architecture fixes only the launcher scheme; giving the
   manager a deterministic identity in the same reserved root is new.
5. **Start-menu subfolder `Programs\PinnedLauncher\`** shared by the manager
   entry and all launcher entries (§4), matching the config-schema §3 example.
