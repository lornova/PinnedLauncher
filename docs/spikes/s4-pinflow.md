## 1. Questions under test

- **Q1 — guided pin flow.** Which one-time pin gesture is smoothest, and how far
  can the app shorten it? Routes under comparison:
  - **R-A** Start → All apps → spike folder → right-click → Pin to taskbar
    (S-3-proven).
  - **R-B** Explorer right-click on the `.lnk` itself.
  - **R-C** deep-link: `s4select.exe <AUMID>` calls
    `SHOpenFolderAndSelectItems` on `shell:AppsFolder\<AUMID>` — if the Apps
    view opens with our entry pre-selected, the guide's residual gesture is one
    right-click (resolves management-window §8.2).
  - **R-D** drag the `.lnk` onto the taskbar (drop-to-pin affordance).
- **Q2 — detection reliability.** Does the `User Pinned\TaskBar` `.lnk` copy
  appear/disappear immediately on pin/unpin, on every route? How does the
  Taskband `Favorites` registry blob (the shell's persisted truth) track it —
  immediate or lazy? This decides how much the management window's pin-status
  heuristic (§3) and the lifecycle reconciliation (architecture §4) can trust
  each signal.
- **Q3 — programmatic unpin.** Does `IStartMenuPinnedList::RemoveFromList`
  (documented for uninstall-time removal of an app's own shortcuts) unpin our
  proxy shortcuts on current Windows 11 — and against which path form: the
  Start-menu source `.lnk`, the `out\` original, or the `User Pinned` copy?
  Must not disturb other pins. Decides UC-3's removal flow: fully programmatic
  vs guided gesture.

## 2. Accepted outcome

Not a go/no-go. The spike closes when each question has a recorded answer and

## 5. Protocol

**Execution: run `.\Invoke-S4Protocol.ps1`** — a guided runner that automates
everything automatable (pin-folder watching with measured latencies, blob
checks, probe tools, branching on outcomes, leftover-pin preflight) and pauses
with one clear instruction whenever a human gesture is needed; every
measurement and answer lands in `results\s4-run-<timestamp>.json` for
transcription into §6. Press `s` during a wait if the requested action turns
out to be impossible. The numbered steps below document what the runner does
and remain the reference if a step must be repeated by hand
(`Watch-PinFolder.ps1` + two terminals, latencies recorded qualitatively).

### 5.1 Route comparison (Q1) with signal observation (Q2)

Per route below: perform the pin gesture → note in W the `Created` event and
its latency → run `.\Get-TaskbandPins.ps1` and note whether the blob already
lists the pin → verify the taskbar button exists → unpin via right-click →
note the `Deleted` event latency and the blob again. Record one §6.1 row and
the corresponding §6.2 rows per route.

1. **R-A**: Start → All apps → **PinnedLauncher S4 Spike** → right-click
   `S4-1 pin test` → Pin to taskbar. Count the clicks/keystrokes from "Start
   opened" to "pinned".
2. **R-B**: in Explorer, right-click `out\S4-1 pin test.lnk` → Pin to taskbar
   (older menu under "Show more options" if absent). Count clicks.
3. **R-C**: in terminal C: `.\bin\s4select.exe PinnedLauncher.S4.PinTest1` —
   record the two printed HRESULTs and what opens (Apps view? entry
   selected?). If a view with the selected entry opened: right-click it → Pin
   to taskbar. Also try the filesystem variant:
   `.\bin\s4select.exe "<full path>\out\S4-1 pin test.lnk"`.
4. **R-D**: drag `out\S4-1 pin test.lnk` from Explorer onto the taskbar —
   record whether a pin/drop affordance appears at all.

### 5.2 Programmatic unpin (Q3)

5. Pin **both** S4-1 and S4-2 via the smoothest working route. Confirm both
   copies exist (W shows two `Created` events).
6. `.\bin\s4unpin.exe "$env:APPDATA\Microsoft\Windows\Start Menu\Programs\PinnedLauncher S4 Spike\S4-1 pin test.lnk"`
   (the Start-menu source). Record all printed HRESULTs; observe: S4-1 button
   gone from the taskbar? `Deleted` event in W (latency)? blob updated? **S4-2
   and all pre-existing pins untouched?**
7. If step 6 did not unpin: repeat against the `User Pinned` copy:
   `.\bin\s4unpin.exe "$env:APPDATA\Microsoft\Internet Explorer\Quick Launch\User Pinned\TaskBar\S4-1 pin test.lnk"`.
8. If needed, third path form: the `out\` original.
9. Re-pin S4-1, then repeat the successful step-6/7 form once for stability.
10. Optional (recommended once): after a programmatic unpin, restart Explorer
    (`taskkill /f /im explorer.exe; start explorer`) — the pin must stay gone
    (no zombie resurrection from the blob).

### 5.3 Cleanup

11. Unpin anything still pinned; then:
    `Remove-Item "$env:APPDATA\Microsoft\Windows\Start Menu\Programs\PinnedLauncher S4 Spike" -Recurse -Force`
    and `Remove-Item .\out -Recurse -Force`.

## 7. Outcome — recorded 2026-08-15

- **Q1 decision — pin-guide flow:** the guide calls
  `SHOpenFolderAndSelectItems` on `shell:AppsFolder\<AUMID>`, which opens the
  Apps view with the launcher's entry **pre-selected**; the user's residual
  gesture is right-click → Pin to taskbar. Management-window §8.2 resolved
  affirmatively (selection, not just folder-open). Fallbacks, in order:
  drag-to-taskbar (works, one drag), Start All-apps route (3 clicks).
- **Q2 statement — detection:** the `User Pinned\TaskBar` `.lnk` copy is a
  synchronous, bidirectional, route-independent signal — verified across four
  pin routes, gesture unpin, programmatic unpin, and a forced Explorer restart.
  It serves as the §5.1 heuristic, the §5.3 pin-guide watcher, and the
  ADR-0009 file-system oracle. The Taskband `Favorites` blob is lazily
  persisted and must not be used for live detection. Display remains
  best-effort informational — the shell owns the truth.
- **Q3 decision — UC-3 unpins programmatically:**
  `IStartMenuPinnedList::RemoveFromList`, passed the **Start-menu source**
  `.lnk`, unpins our proxy shortcuts on current Windows 11: immediate, isolated
  (no other pin touched), and persistent across an Explorer restart. Note for
  implementation: the call returns **S_FALSE** on success — check
  `SUCCEEDED(hr)`, not `hr == S_OK`. The guided gesture remains the fallback
  only if the call fails.
